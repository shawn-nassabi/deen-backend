<objective>
DEE-67 follow-up: hold Quran translation out of the batch MT job in `scripts/translate_references.py`. The stored Quran text (`english_quran_translation`) is already an English rendering of the Arabic — machine-translating it further would pivot-translate (Arabic → English → target language), double-translating the literal Qur'anic text. Quran should use published direct translations instead; hadith and tafsir MT (translated from their own stored English) are unaffected and remain enabled. This is a deliberate, reversible hold — not a schema or logic change.

Purpose: Prevent a low-quality double-translation of Qur'anic text from ever being generated by the existing `--ref-type all` default, while keeping hadith/tafsir MT fully functional.

Output:
- `DISABLED_REF_TYPES` module-level constant (currently `{"quran_translation"}`) with an inline comment explaining the pivot-translation rationale and how to re-enable
- `_resolve_enabled_ref_types(ref_type_arg: str) -> list[str]` helper, used by `main()`, that filters the requested ref_types against `DISABLED_REF_TYPES`, logs a warning per skipped type, and returns the enabled subset
- `main()` logs an error and returns early (no Pinecone/Anthropic/DB client construction, no `run_batch()` call) when the enabled subset is empty
- Deterministic unit tests covering both the `--ref-type all` case (hadith + tafsir_text only) and the `--ref-type quran_translation` case (empty enabled set)
</objective>
