# Quick Task 260509-3cd: Real-Time Fiqh SSE Status Events

## Goal

Eliminate the 10–15 second silent gap between "Fiqh query detected..." and the
final answer. Today, fiqh sub-graph nodes accumulate status events into
`FiqhState["status_events"]` and `pipeline_langgraph.py` replays the entire trail
*after* the sub-graph completes (via the `fiqh_subgraph` node-arrival event from
`agent.astream`). The user sees no progress until the trail rapid-fires right
before the answer streams.

This task surfaces those events in real-time as each fiqh stage starts —
`Decomposing... → Retrieving... → Filtering... → Assessing...` — so the
frontend updates progressively rather than all at once at the end.

## Context

- Prior task `260420-t2v` explicitly deferred the real-time refactor (see its
  `decisions:` block: "Surface fiqh status events retrospectively (batch at
  sub-graph completion), not real-time. Full astream refactor of fiqh_subgraph
  is out of scope"). This is the deferred fix.
- LangGraph 0.2.64 does not expose `langgraph.config.get_stream_writer`
  (introduced in 0.3.x), so we use a contextvar-bound `asyncio.Queue` instead
  of LangGraph's native custom-stream mechanism. Functionally equivalent.

## User Decisions (captured in chat)

- **Iteration UX:** First pass emits real per-stage labels
  (Decomposing/Retrieving/Filtering/Assessing). Iteration ≥ 2 collapses to a
  single "Searching deeper for evidence..." (emitted from `_refine_node`).
- **Keep-alive:** Retain "Processing fiqh query (this may take 10-15
  seconds)..." as a brief intro before the first real-time stage event.
- **Cleanup scope:** Keep retrospective replay in `pipeline_langgraph.py` as a
  fallback; activate only when the real-time queue produced nothing.

### Task 4 — Producer/consumer refactor in pipeline_langgraph

**File:** `core/pipeline_langgraph.py`

Refactor `response_generator()` to multiplex two event sources via a single
`asyncio.Queue`:

1. Create `output_queue: asyncio.Queue` and bind it to the `fiqh_status_queue`
   contextvar via `set()/reset()` (in a try/finally).
2. Move the existing `async for event in agent.astream(...)` loop into an
   inner `_agent_producer()` coroutine. Instead of yielding SSE strings
   directly, it `await output_queue.put(sse_str)` for each translated event.
   Mutable state (`final_state`, `emitted_tool_call_ids`) is captured in
   closure boxes so the post-loop logic can still use the final state.
3. Skip emitting `NODE_STATUS_MESSAGES["fiqh_subgraph"]` from the producer
   loop (the keep-alive is now pushed via the queue from Task 3 — emitting
   it again from astream would duplicate).
4. Gate the retrospective `fiqh_status_events` replay on
   `fiqh_realtime_count == 0`. If the real-time path emitted at least one
   fiqh status event, skip the retrospective replay; mark `fiqh_trail_emitted`
   either way (so the canned fallback at the post-loop body remains
   suppressed when fiqh has been covered).
5. Run the producer as `asyncio.create_task(...)`. The outer
   `response_generator` body becomes a `while True: item = await
   output_queue.get()` loop that yields items based on type:
   - `_AGENT_DONE` sentinel → break.
   - `dict` with `step`+`message` → wrap as `status` SSE, increment
     `fiqh_realtime_count`, yield.
   - `str` (SSE event from producer) → yield as-is.
6. After the consumer loop, `await producer_task` to propagate any exception.
   The rest of `response_generator` (early-exit, fiqh streaming, hadith
   streaming, done) is unchanged.
7. Reset the contextvar in a `finally` block.

  already ignore unknown step values per the existing extensibility note.

  ephemeral, just like today).

  bootstrap failure documented in `260420-t2v/deferred-items.md` — same
