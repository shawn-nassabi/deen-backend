# Plan: DEE-51 chatbot error resilience + observability

## Goal

Production users see "I apologize, but I'm having trouble responding right now" intermittently with no Sentry trace. Two root causes addressed in one quick task:

1. **Silent failure paths** — Pinecone errors and several LLM error paths use `print()` or `logger.warning`, so they bypass Sentry's `event_level=logging.ERROR` filter.
2. **No retry layer** — `ChatAnthropic` constructors take langchain-anthropic defaults (2 retries, no app timeout); Pinecone calls have no retry at all. Transient infrastructure blips become user-visible failures.

## Tasks

### Task 1 — Add `core/resilience.py` shared retry policy

**files:** `core/resilience.py` (new)

**action:** Create a small module exposing two tenacity-based async retry decorators:
- `anthropic_retry` — retries on `anthropic.APIStatusError` (status 5xx, 408, 409, 429, 529), `anthropic.RateLimitError`, `anthropic.APIConnectionError`, `anthropic.APITimeoutError`. Policy: `stop_after_attempt(3)`, `wait_exponential(multiplier=1, min=0.5, max=8)` with jitter, `before_sleep` hook that does `logger.warning("anthropic transient error, retrying", extra={...})`.
- `pinecone_retry` — retries on `pinecone.exceptions.PineconeApiException` (when status 5xx) plus generic `httpx.HTTPError` / `OSError` for connection errors. Same backoff policy.

**verify:** Decorators import cleanly; `python -c "from core.resilience import anthropic_retry, pinecone_retry"` succeeds.

**done:** New file committed.

## Must-haves

- Sentry receives an event for every Pinecone retrieval failure on the agentic path.
- Sentry receives an event for every LLM exception on the fiqh subgraph and main agent.
- A single transient Anthropic 529/503/429 no longer bubbles up to the SSE error event — three retry attempts spaced 0.5s/2s/8s absorb the transient.
- A single transient Pinecone 5xx no longer drops a query to zero retrieved docs — three retry attempts absorb the transient.
- No streaming output (`.astream`) is wrapped in retry logic (avoids duplicate-token risk).

- Non-error debug `print()` statements (`INSIDE ...`) elsewhere
