```python
def record_cache_metrics_breadcrumb(
    *,
    cache_efficiency_ratio: float,
    cache_read_tokens: int,
    cache_creation_tokens: int,
    iterations: int,
) -> None:
    """Emit a per-turn cache-efficiency breadcrumb on the current Sentry scope.

    No-op when SENTRY_ENABLED is False (D-09) — local dev / unit tests must not
    require Sentry. Called once per /chat/stream/agentic (or /chat/agentic) turn
    at the SSE `done` boundary (D-01, D-02). Caller pre-computes the ratio and
    handles the cold-cache (denominator 0) case as 0.0 (D-06).

    Note: correlation_id is auto-attached via the request's isolation scope
    (set by bind_sentry_scope in api/chat.py); the data dict carries diagnostic
    counts only.

    Args:
        cache_efficiency_ratio: cache_read / (cache_read + cache_creation), 0.0..1.0
        cache_read_tokens: sum across all _agent_node iterations this turn
        cache_creation_tokens: sum across all _agent_node iterations this turn
        iterations: number of _agent_node calls this turn
    """
    if not SENTRY_ENABLED:
        return
    sentry_sdk.add_breadcrumb(
        category="cache_metrics",
        level="info",
        message="cache_efficiency",
        data={
            "cache_efficiency_ratio": cache_efficiency_ratio,
            "cache_read_tokens": cache_read_tokens,
            "cache_creation_tokens": cache_creation_tokens,
            "iterations": iterations,
        },
    )
```

|----------|-------------|
| Application -> Sentry SDK | Internal numeric metrics cross into Sentry via `add_breadcrumb`. The breadcrumb data dict is constructed entirely from server-side numeric counts — no user input, no PII. |
| ChatState in-memory | New int fields live entirely in the per-request LangGraph state. No persistence, no cross-request shared memory. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-19-01 | Information Disclosure | `record_cache_metrics_breadcrumb` data dict | accept | Data dict carries only numeric counts (`cache_efficiency_ratio` float, three ints). No user query, no session_id, no PII. The existing `before_send` PII scrubber in `core/sentry.py:_scrub_pii` provides defense-in-depth on error events; breadcrumbs are only delivered alongside an event so they inherit the same scrubbing pipeline. |
| T-19-02 | Tampering | ChatState `cache_*_tokens_total` fields | accept | Fields are mutated only inside the LangGraph node loop within a single async task. No cross-request access; `MemorySaver` checkpointer is in-process. No threat surface. |
| T-19-03 | Denial of Service | Sentry SDK call when `SENTRY_ENABLED` is true and Sentry is unreachable | mitigate | Sentry SDK's `add_breadcrumb` is non-blocking and handles its own backoff/dropping. The `if not SENTRY_ENABLED: return` guard ensures local/test paths never reach the SDK. No additional mitigation needed. |
| T-19-04 | Repudiation | Breadcrumb integrity | accept | Breadcrumbs are diagnostic, not audit. No durability, no integrity guarantee required. |
