# Milestone v1.4: LLM Input Caching

**Status:** ✅ SHIPPED 2026-05-04
**Phases:** 17–19
**Total Plans:** 9
**Requirements:** 8 (CACHE-01..04, STRUCT-01..02, OBS-01..02)

## Overview

Reduced Anthropic API costs by applying Claude prompt caching to all eligible LLM call sites. The ChatAgent's tool definitions and system prompt are cached together as a single prefix (~5,149 tokens, above the 2,048-token threshold). All module-level system prompts across the FAIR-RAG pipeline were refactored from the silent-stripping `ChatPromptTemplate` pattern to content-block format. Per-session cache efficiency ratio is now emitted as a Sentry breadcrumb.

**Timeline:** 2026-05-03 → 2026-05-04 (2 days)
**Files changed:** 22 Python files (+909 / -128 lines)

## Milestone Summary

**Key Decisions:**
- Combined tools + system prompt prefix (~5,149 tokens) is the only eligible cache breakpoint for the ChatAgent — system prompt alone (1,427 tokens) is below the 2,048-token Sonnet minimum
- `AnthropicPromptCachingMiddleware` does not exist in `langchain-anthropic==0.3.22` — documented as anti-pattern
- `ChatPromptTemplate.format_messages()` silently strips `cache_control` (GitHub #26701) — all system prompts must use `SystemMessage(content=[...])` content-block lists
- Never cache `modules/enhancement/enhancer.py` — Haiku 4.5 requires 4,096-token minimum; enhancer prompt is ~330 tokens
- Never put `cache_control` inside `ToolMessage.content[]` — causes `invalid_cache` API error (GitHub #34920)
- Use `response.response_metadata["usage"]` for cache metrics, not `response.usage_metadata` — LangChain wrapper double-counts cached tokens on streaming calls (GitHub #32818)

**Issues Resolved:**
- `@tool(extras=...)` is not a valid API in langchain-core==0.3.84 — used `convert_to_anthropic_tool()` + dict mutation instead
- `_generate_fiqh_response_node` missed in 18-02 plan scope — hotfixed during Phase 18 verification
- Wave 3 worktree conflict from rogue commit bringing Phase 17/18 changes — cherry-picked 3 clean commits
- CR-01 SSE exception message leak pre-existing at `core/pipeline_langgraph.py:434` — fixed in code review pass before deploy

**Issues Deferred:**
- OBS-02: measured cache hit rate requires live production traffic — post-deploy manual step per DEE-50-POST-DEPLOY-CHECKLIST.md
- HIST-01: Second `cache_control` breakpoint on accumulated message history — deferred until Phase 17 hit rates confirmed in production
- LEGACY-01: Legacy generator system prompt caching — borderline at ~1,200 tokens estimated

**Technical Debt Incurred:**
- Non-streaming `chat_pipeline_agentic` path has no cache breadcrumb — streaming path is the production path; deferred to future plan
- `agent_tests/test_prompt_cache.py` requires live Anthropic API key — not in CI; runs manually
