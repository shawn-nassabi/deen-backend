<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→/chat/stream/agentic | User-controlled user_query, session_id, config JSON cross into agentic pipeline |
| client→/chat/agentic | Same as above for non-streaming variant |
| log sink→Sentry | extra={} fields from chat handlers flow to Sentry Logs via LoggingIntegration |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-07 | Information Disclosure | api/chat.py logger.info start log | mitigate | Start log uses `query_length` (int) not `user_query` (string) — per D-05. Query text never reaches Sentry Logs. The `before_send` hook (Phase 13) strips request body from error events as defense-in-depth. |
| T-14-08 | Information Disclosure | api/chat.py except blocks | mitigate | `logger.error(exc_info=True)` sends exception details to Sentry only, not to the HTTP response. HTTPException detail is generic "Internal Server Error". No raw exception text leaked to client. |
| T-14-09 | Tampering | correlation_id in chat extra={} | accept | correlation_id is server-generated UUID from CorrelationIdMiddleware ContextVar. Client cannot spoof it. |
| T-14-10 | Denial of Service | Config parse in agentic handler | accept | Malformed config falls back to default AgentConfig (D-09). The WARNING log does not re-raise — handler continues. No DoS vector from config parse errors. |
| T-14-11 | Elevation of Privilege | user_id in Sentry tags via bind_sentry_scope | accept | user_id is the Cognito `sub` claim — an opaque UUID, not username/email. No PII. Sentry scope tags are internal observability data, not returned to client. |
</threat_model>
