| Boundary | Description |
|----------|-------------|
| user_query → pipeline logs | User-supplied text must never flow into log extra={} fields (flows to Sentry Logs stream) |
| logger.error → Sentry | LoggingIntegration fires on ERROR; a duplicate capture_exception() would create two Sentry events for one exception |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Information Disclosure | pipeline_langgraph.py log extra={} | mitigate | D-05 + D-06: `user_query` and `working_query` are excluded from all extra={} dicts; only session_id, correlation_id, target_language, node, and error string are logged |
| T-15-02 | Denial of Service | logger.debug("Node traversal") in streaming loop | mitigate | D-01: traversal logs are DEBUG only; Sentry LoggingIntegration threshold is INFO — these never reach Sentry and do not consume Sentry log quota |
| T-15-03 | Repudiation | Duplicate Sentry events on SSE generator exception | mitigate | D-02 + D-09: logger.error(exc_info=True) is the sole capture mechanism; capture_exception() is explicitly forbidden; verified by acceptance_criteria grep for capture_exception returning 0 |
| T-15-04 | Information Disclosure | retrieval_tools.py error log extra={} | mitigate | D-08: extra={} contains only correlation_id and error string — no query parameter (user input) logged |
</threat_model>
